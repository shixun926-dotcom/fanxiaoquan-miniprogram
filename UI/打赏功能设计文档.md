## 1. 需求背景

饭小圈已具备完整的内容与社交体系，项目需要一个"用户自愿支持开发者"的轻量入口。客户要求的核心是**有温度的感谢**而非商业化打赏：用"请饭小圈吃顿饭"代替"付钱"，用一枚可爱的饭碗小吉祥物徽章作为回馈。同时把"意见反馈 / 我的反馈"从我的页迁入新增的"更多"页，避免我的页首屏过载。

本方案的价值判断（`[PM hypothesis]`）：打赏是学生项目的合理非营利尝试——入口低调、标语温情、回馈是纪念徽章而非权益；徽章复用现有兑换码与徽章系统，实施成本低。

## 2. 目标、非目标与核心场景

### 2.1 目标

- 我的页首行从"仅退出"改为"退出 + 更多"，间距与色系符合设计系统。
- 新增"更多"页（标题仅"更多"两字）：收纳意见反馈、我的反馈，并新增"打赏开发者"入口。
- 新增"打赏开发者"页：微信赞赏码（上）+ 爱发电（下）两张二维码原封不动展示、可长按识别；含温情标语与"不打赏"自由度。
- 打赏后用户可领取**打赏徽章**：提示文案"感谢您的打赏，你获得打赏徽章！兑换码为：xxxxx"，凭码兑换后徽章出现在徽章墙。
- 打赏徽章与既有 4 个功能图标、15 枚成就徽章同属一套设计系统。

### 2.2 非目标

- 不做支付链路（不接微信支付 / 不内嵌充值）；打赏走二维码外部完成。
- 不做打赏到账自动感知（小程序无法监听赞赏到账，见 §5.3 领取机制）。
- 打赏等级（Lv.1–5）本期不落地，仅预留设计规范。
- 打赏不提供任何权益加成（纯纪念徽章）。

### 2.3 核心场景（按优先级）

| 优先级 | 场景 | 说明 |
| --- | --- | --- |
| P0 | 找到入口 | 我的页点"更多"→ 更多页 → 打赏开发者 |
| P0 | 扫码打赏 | 打赏页选择微信赞赏码或爱发电，长按识别完成打赏 |
| P0 | 领取徽章 | 点"我已打赏"→ 获得兑换码 → 兑换 → 徽章墙上出现打赏徽章 |
| P1 | 反馈迁移 | 意见反馈 / 我的反馈从我的页迁入更多页，路径可用 |

## 3. 打赏徽章设计（已出图）

核心元素 = **饭碗小吉祥物抱着爱心 + "打赏支持"丝带**。用户第一眼看到的是"我请饭小圈吃一顿饭"，而不是"我要付钱"。

## 4. 功能设计

### 4.1 我的页首行改造（F1）

现状：`pages/profile/profile.wxml` 首行 `profile-head` 卡片右侧仅一个"退出 / 登录"胶囊按钮。

改造：

```
[头像] 昵称                 [退出]  [更多]
        微信登录 · 昵称头像来自授权
```

- "退出"保留现状（红色浅底 `#FDEDE6` / 字 `#E5484D`，登录态显示"退出"、未登录显示"登录"）。
- "更多"新增在退出右侧：暖色浅底 `#FFF1E6`、文字 `#FF8A1F`、1rpx `#FFD9C4` 描边，与退出同尺寸同高度。
- **间距**：两按钮之间 `16rpx` 间距（`gap`）；整体距卡片右缘 `24rpx`。
- **色系**："更多"用品牌橙（次要入口），"退出"用警示红（危险操作），形成明确区分；"更多"视觉权重不高于"退出"。
- 点击"更多" → `wx.navigateTo` 到更多页；点击"退出"逻辑不变。

### 4.2 更多页（F2）

新增页面 `pages/more/more`，顶部导航标题**仅"更多"两个字**。

```
┌─────────────────────────────┐
│ ← 更多                        │  顶部导航：更多
├─────────────────────────────┤
│  🟠[徽章]  意见反馈          › │  从我的页迁入
│  🟡[徽章]  我的反馈          › │  从我的页迁入
│  ─────────────────────────  │
│  ❤️[徽章]  打赏开发者        › │  新增入口（独立分区）
│            请饭小圈吃顿饭 🍚  │  副文案
└─────────────────────────────┘
```

- 列表卡片沿用"餐垫卡"样式（暖线描边、暖阴影）。
- 三行入口：意见反馈（图标 `feedback-128.png`）、我的反馈（图标 `my-feedback-128.png`）、打赏开发者（图标 `reward-badge-128.png`）。
- 打赏开发者单独一个区块（上方一条分隔线），副文案"请饭小圈吃顿饭 🍚"。
- **迁移**：从 `profile.wxml` 移除"意见反馈 / 我的反馈"两个入口行（它们原来在首行区 / 列表区），改由更多页承接；跳转逻辑与页面文件不变。
- 登录态：未登录也可进更多页，点击各入口时按需引导登录（打赏领取徽章需登录）。

│   请饭小圈吃顿饭 🍚           │  主标语
│ 请根据您经济状况打赏，          │  副标语（客户指定文案）

│  │ 爱发电 · 打赏           │  │

- 爱发电卡片注明"我的主页：**开发中**"（网址暂不配置，后补）。
- 副标语为客户指定文案，一字不改："请根据您经济状况打赏，我们都要好好的生活~"。

### 4.4 打赏徽章领取（F4）

打赏在小程序外完成（扫码 → 外部平台），小程序无法自动感知到账，采用**信任制领取 + 兑换码**（学生项目合理取舍，信任制已确认）：

1. 用户点"我已打赏，领取打赏徽章"（需登录）。
2. 云函数生成**兑换码**（绑定打赏徽章）并返回；**每次点击"我已打赏"都会展示兑换码**——首次点击生成并绑定该用户，之后每次点击返回同一枚兑换码（可随时找回，同时避免无限生成）。
3. 弹层提示（客户指定文案）：
   > 感谢您的打赏，你获得打赏徽章！兑换码为：`xxxxx`
4. 用户复制兑换码 → 在"我的页 → 兑换码"输入兑换 → 获得**打赏开发者徽章**（出现在徽章墙，并可展示在帖子昵称行）。

> 说明：兑换码每人一枚、永久有效；未兑换前可在兑换码入口随时使用；重复点击"我已打赏"只再次展示同一枚码，不再拒绝。

## 5. 数据与规则

### 5.1 徽章扩展（`utils/badges.js` + 云函数 `BADGES` 同步）

新增第 16 枚徽章：

| key | 名称 | 类别 | 稀有度 | target | 图标 |
| --- | --- | --- | --- | --- | --- |
| `reward` | 打赏开发者 | 特殊 | 特殊 | 1 | `reward-badge`（PNG / SVG） |

前后端同步（沿用现有 `BADGES` 同步模式），解锁走现有徽章解锁链路。

### 5.2 兑换码扩展（`codes` 集合）

- `codes` 文档新增字段：`type: 'badge'`、`badgeKey: 'reward'`（普通码维持 `type: 'exp'` 语义不变）。
- 打赏码属性：`usedCount` 上限 **1**（一次性）、每用户每码限兑换一次（`redeems` 按 `openid:code` 去重，沿用现有机制）。
- `codes.redeem` 云函数扩展：`type === 'badge'` 时调用徽章解锁（复用现有徽章解锁函数），并返回成功提示。

### 5.3 领取接口（新增云函数动作）

```
reward.claim = { }   →  { code, badgeKey: 'reward', repeated }
```

规则：需登录；**每次点击都返回兑换码**（首击生成并绑定用户 `rewardCode`，之后返回同一枚，`repeated: true` 标记重复点击）；码与用户一一绑定、永久有效；重复点击不拒绝，仅再次展示。

### 5.4 边界与异常

| 异常 | 处理 |
| --- | --- |
| 未登录点"我已打赏" | 弹登录面板，登录后继续 |
| 重复点击"我已打赏" | 不拒绝：返回同一枚兑换码（`rewardClaimed` 已置位时读取 `users.rewardCode`） |
| 二维码加载失败 | 显示占位 + 重试 |
| 兑换码未及时兑换 | 码永久有效（一次性，不设过期）`[待确认]` |
| 爱发电主页未配置 | 显示"开发中"占位文案，不显示死链 |
| 信任制滥用（未打赏也领取） | 学生项目默认接受；可后续接爱发电自动回复 / 赞赏回调升级 `[待确认]` |

## 7. 分期、验收与待确认

### 7.1 分期

- V1：F1–F4 全链路（首行改造 → 更多页 → 打赏页 → 领取徽章）。
- V2（可选）：打赏等级徽章（Lv.1–5）、到账自动发放（爱发电自动回复 / 赞赏回调）。

### 7.2 验收标准

1. 我的页首行显示"退出 + 更多"，间距 16rpx、色系区分（红/橙），点击更多进入更多页。
2. 更多页标题仅"更多"两字；意见反馈、我的反馈可正常进入；打赏开发者入口带副文案。
3. 打赏页两张二维码图片原封不动展示、可长按识别；爱发电注明"我的主页：开发中"；副标语一字不差。
4. 未登录点"我已打赏"弹登录面板；登录后领取成功弹出提示"感谢您的打赏，你获得打赏徽章！兑换码为：xxxxx"。
5. 用兑换码兑换后，徽章墙出现"打赏开发者"徽章（特殊稀有度，彩色展示）。
6. 同一用户重复点击"我已打赏"每次都展示同一枚兑换码（不拒绝）；兑换码每人一枚、兑换一次后失效。

4. 打赏徽章稀有度定为"特殊"（与开发者徽章同级）是否合适？`[待确认]`。
5. 打赏等级（Lv.1–5）本期是否落地？默认 V2 `[待确认]`。
