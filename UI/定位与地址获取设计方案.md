# 饭小圈 · 定位与地址获取设计方案

> 版本：V0.1（评审稿）
> 日期：2026-08-10
> 范围：`wx.getLocation` 统一封装（权限 / 精度 / 频率 / 缓存）+ 逆地址解析（地址文案）+ 附近页接入
> 依据：微信官方 `wx.getLocation` 接口文档（含 2022-07-14 声明规则、2.17.0 频率限制、类目开通要求）
> 本文件只描述"做什么、按什么规范做"，推断以 `[待确认]` 标注。

---

## 1. 需求背景

饭小圈的"附近 50km"依赖用户定位：当前实现为**登录时取一次定位**（`login-panel` → `wx.getLocation({type:'wgs84'})` → `user.set({lat,lng})`），云函数 `nearby.list` 按 `users.lat/lng` 做 Haversine 距离过滤。现状问题：

- 定位逻辑散落在登录面板里，无统一封装；附近页无法主动刷新定位。
- 无**地址文案**（逆地理编码），用户不知道"当前定位在哪"。
- 无**频率与缓存管理**（`wx.getLocation` 2.17.0 起有调用频率限制）。
- 上线前合规未闭环：`app.json` 已声明 `scope.userLocation`，但**类目审核与后台接口开通**、**隐私协议声明位置信息**尚未处理。

本方案把"取定位 + 逆地址解析"收敛为一个统一接口，一处封装、处处复用（登录、附近页、发帖定位）。

## 2. 目标、非目标与核心场景

### 2.1 目标

- 统一封装定位获取（`utils/location.js`）：类型 `gcj02`、高精度、超时降级、缓存、频率保护、授权引导。
- 新增**当前地址文案**：逆地理编码得到"城市 / 区"，附近页顶部展示"当前定位：xx市xx区"。
- 登录时自动取定位（沿用现状语义）；附近页可主动刷新定位。
- 明确上线前合规事项：类目开通、接口声明（已完成）、隐私协议。

### 2.2 非目标

- 不做持续定位（`wx.onLocationChange`，耗电高）。
- 不做地图展示 / `wx.openLocation`（列为 V2 候选）。
- 不做 POI 搜索、位置分享、位置签到。

### 2.3 核心场景（按优先级）

| 优先级 | 场景 | 说明 |
| --- | --- | --- |
| P0 | 登录自动定位 | 登录后静默取定位存 `users.lat/lng`（拒绝不阻塞） |
| P0 | 附近页显示地址 | 进入附近，顶部显示"当前定位：xx市xx区"，无定位显示引导卡 |
| P1 | 手动刷新定位 | 点地址 / 刷新按钮重新定位（走频率保护） |
| P1 | 发帖带位置 | 发帖时写入当前 `lat/lng`（沿用现状） |

## 3. 现状盘点（代码事实）

| 项 | 现状 |
| --- | --- |
| 权限声明 | `app.json` 已声明 `permission.scope.userLocation` ✓ |
| 定位获取 | `login-panel` 登录后 `wx.getLocation({type:'wgs84'})` → `user.set({lat,lng})`，拒绝不阻塞 |
| 附近过滤 | 云函数 `nearby.list` 读 `users.lat/lng`，Haversine ≤50km；无定位返回 `needLocation: true` |
| 引导卡 | feed 附近 tab 已有"开启定位"引导卡与 `enableLocation` |
| 逆地理编码 | **无**（无地址文案） |
| 频率 / 缓存 | **无**（每次登录取一次，未考虑 2.17.0 频率限制） |
| 合规 | 类目开通、隐私协议**未处理** |

## 4. 接口设计

### 4.1 统一定位工具 `utils/location.js`

```js
// 返回 Promise<{ latitude, longitude, accuracy, address, city, district, ts, from: 'live'|'cache' }>
ensureLocation({ refresh = false } = {}) → Promise
```

| 关注点 | 设计 |
| --- | --- |
| 坐标系 | `type: 'gcj02'`（官方建议；与逆地理编码服务坐标系一致，`wx.openLocation` 可用） |
| 精度 | `isHighAccuracy: true`、`highAccuracyExpireTime: 5000`；超时自动降级普通定位 |
| 缓存 | 定位结果写本地缓存 `fxq_loc`（含 `lat/lng/address/city/ts`），**TTL 15 分钟**；`refresh:false` 时缓存未过期直接复用 |
| 频率保护 | 同一会话内两次"真实调用"间隔 ≥ 1 分钟（防 2.17.0 频率限制）；不满足则用缓存 |
| 授权 | `wx.getSetting` 查 `scope.userLocation` → 未授权走 `wx.authorize`；已拒绝（返回 false）直接引导 `wx.openSetting`（按钮触发，避免弹窗轰炸） |
| 上报 | 定位成功后 `api.setUser({ lat, lng })`（沿用现有 `user.set`）；云函数端无改动 |

调用方：登录面板（登录后 `ensureLocation()`）、附近页（进入时 / 手动刷新 `ensureLocation({refresh:true})`）、发帖（复用当前 `users.lat/lng`，无需重复取）。

### 4.2 逆地址解析（地址文案）

| 方案 | 说明 |
| --- | --- |
| A（推荐） | 接入**腾讯位置服务**（WebService 逆地理编码），`gcj02` 直接匹配；返回 `address`、`ad_info.city`、`ad_info.district`；key 配置 + 合法域名 |
| B | 逆编码请求走**云函数代理**（key 放服务端不暴露，需为云函数开通外网域名）`[待确认]` |

- 展示粒度：默认**城市 + 区**（"北京市·海淀区"）；街道级按需开启。
- 结果缓存：地址与坐标同缓存（15 分钟 TTL），避免频繁逆编码产生服务费。
- 兜底：逆编码失败时显示"当前位置"，不阻塞附近功能。

### 4.3 云函数扩展（最小改动）

| 位置 | 改动 |
| --- | --- |
| `user.set` | 新增可选字段 `address` / `addressTs`（透传，可空，兼容老数据） |
| `user.get` | 返回 `address`（附近页头部显示用） |
| `nearby.list` | **不改**（仍按 `users.lat/lng` 过滤） |

### 4.4 页面接入

```
附近 tab 头部：
📍 当前定位：北京市 · 海淀区   [刷新]
（无定位 → 现有「开启定位」引导卡）
```

- 进入附近页：`ensureLocation()` → 有缓存直接显示地址；无缓存取定位 → 逆编码 → 显示。
- 点刷新：`ensureLocation({refresh:true})`（走频率保护）。
- 地址为空 / 失败：显示"当前位置"；附近列表逻辑不变。

## 5. 频率限制与合规（上线前必须处理）

| 项 | 要求 | 状态 |
| --- | --- | --- |
| `app.json` 声明 `scope.userLocation` | 2022-07-14 后发布的小程序必须声明 | ✅ 已声明 |
| **类目审核 + 接口开通** | 需在对应类目下（工具-信息查询、餐饮服务等），于小程序后台「开发 - 开发管理 - 接口设置」自助开通 `getLocation`；未开通代码提审会被拦截 | ⚠️ 上线前完成 |
| 调用频率 | `wx.getLocation` 2.17.0 起频率限制 → 用缓存 TTL + 会话间隔规避 | 本方案内实现 |
| 隐私协议 | 小程序隐私保护指引需声明"位置信息"收集用途（定位附近的人 / 显示当前位置） | ⚠️ 上线前完成 |
| 开发者工具 | 工具定位为 IP 模拟、有误差、仅支持 `gcj02` → 真机为准 | 备注 |

## 6. 边界与异常

| 异常 | 处理 |
| --- | --- |
| 用户拒绝授权 | 附近页显示引导卡（已实现）；按钮触发 `wx.openSetting`；不反复弹窗 |
| 定位超时 / 失败 | 高精度超时降级普通定位；仍失败用缓存；无缓存 → `needLocation` |
| 缓存过期且拒绝授权 | 显示引导卡 + 缓存里的旧地址（标注时间）`[待确认]` |
| 逆编码失败 / 无网络 | 显示"当前位置"，附近功能不受影响 |
| 精度差（accuracy 大） | 不阻断；提示"定位精度较低，仅供参考" `[待确认]` |
| 离开小程序后调用 | 接口不可用 → 冷启动重新 `ensureLocation`（缓存兜底） |
| 坐标口径 | 全链路统一 `gcj02`（避免 wgs84 与 gcj02 混用导致附近偏移） |

## 7. 影响分析

| 维度 | 影响 |
| --- | --- |
| 新增 | `utils/location.js`（定位 + 缓存 + 逆编码封装）；逆地理编码服务接入（key / 域名） |
| 页面 | 登录面板改为调用 `ensureLocation`；feed 附近 tab 头部加"当前定位"与刷新 |
| 云函数 | `user.set` / `user.get` 增 `address`（可空，零破坏） |
| 配置 | 小程序后台：类目开通 getLocation、隐私协议声明、第三方服务域名白名单 |
| 既有规则 | 附近 50km 过滤、发帖位置、社交 / 徽章 / 检索 / 反馈均不受影响 |

## 8. 分期、验收与待确认

### 8.1 分期

- V1：`utils/location.js` 统一封装（权限 / 精度 / 缓存 / 频率）+ 逆编码（城市区级）+ 附近页地址显示与刷新 + 登录接入。
- V2（候选）：`wx.openLocation` 地图跳转、街道级地址、定位精度提示。

### 8.2 验收标准

1. 登录后自动取定位并写入 `users.lat/lng`；拒绝授权不阻塞登录。
2. 进入附近页显示"当前定位：xx市xx区"；无定位显示引导卡。
3. 15 分钟内重复进入附近页**不重复调用** `wx.getLocation`（缓存生效，符合频率限制）。
4. 手动刷新走频率保护：1 分钟内重复刷新复用最近一次定位。
5. 授权拒绝后点击引导卡按钮可打开设置页；开启后回到小程序可正常定位。
6. 全链路坐标 `gcj02`，附近距离与真机一致（± 可接受误差）。
7. 逆编码失败时显示"当前位置"，附近列表不受影响。
8. 老用户无 `address` 字段时前端兼容，不报错。
