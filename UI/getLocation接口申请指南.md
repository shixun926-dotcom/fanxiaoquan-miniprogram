# 饭小圈 · getLocation 接口申请文案与指南

> 目的：申请微信小程序 `wx.getLocation` 接口权限（当前申请被驳回，按本文修正后重新提交）
> 参照：微信官方成功案例（共享单车 / 自提服务）的写法结构

---

## 1. 为什么会被驳回（先自查这 4 项）

微信审核 getLocation 的实质是：**你的业务必须真实、具体地用到定位，且类目在开放范围内**。驳回常见原因：

| # | 驳回原因 | 自查 |
| --- | --- | --- |
| 1 | **类目不符**（最常见） | 小程序后台的服务类目必须是开放类目之一（餐饮服务、生活服务、工具-信息查询、旅游、交通服务等）。如果当前类目是"社交"或不在列表内，写什么文案都会被拒 → **先调整 / 添加一个匹配类目** |
| 2 | **申请原因与接口用途不匹配** | 原因写得太泛（如"需要定位功能"），没说明"定位数据具体用来做什么、完成什么业务" → 用第 2 节模板 |
| 3 | **申请的接口超出实际需要** | 只需要一次性定位却申请了 `wx.onLocationChange` / `wx.startLocationUpdate`（持续定位），审核从严 → **只勾 `wx.getLocation`** |
| 4 | **辅助图片与申请场景对不上** | 截图里没有能证明"业务确实用到了定位"的页面 → 按第 4 节截图 |

## 2. 申请原因模板（直接复制，改成你的页面名）

```
因当前业务涉及「附近 50km 晒吃内容」功能，用户进入"附近"栏目时，
需获取用户当前地理位置，用于：

1. 以用户所在位置为中心，筛选并展示 50km 范围内其他用户发布的
   晒吃帖 / 美食内容，匹配附近的餐饮动态；
2. 计算并展示帖子与用户之间的实时距离（如"1.2km"），
   帮助用户判断就近美食、快速决定吃什么；
3. 用户发帖时记录位置信息，供其他用户检索附近内容，
   完成"发现附近美食 → 到店 / 点外卖"的本地生活服务闭环。

故申请 wx.getLocation 接口（一次性定位，非持续定位），
用于匹配附近美食内容与展示距离信息。
```

写法要点（对照成功案例）：

- **开头句式照抄**："因当前业务涉及……需获取用户当前地理位置，用于……"（与案例 2 完全一致的结构）
- **业务闭环**：一定要落到"完成××闭环 / 提供××服务"，不能只说"用于展示附近"
- **接口明确**：只提 `wx.getLocation`，写明"一次性定位、非持续定位"（和案例 1 申请持续定位形成对比，显得更克制）
- **避免"泛词"**：不要写"提升用户体验""方便用户"这类话

## 3. 类目选择建议

`wx.getLocation` 开放类目中，与饭小圈最贴近的：

| 候选类目 | 匹配度 | 说明 |
| --- | --- | --- |
| 餐饮服务 - 点餐平台 | 高（推荐） | 饭小圈 = 决定吃什么 + 查找附近美食，属于本地餐饮场景 |
| 生活服务 | 中 | 定位用于附近内容展示 |
| 工具 - 信息查询 | 中 | 定位查询附近美食信息 |

> 操作：小程序后台 → 设置 → 基本设置 → 服务类目，添加一个匹配类目（可保留原类目作为主类目）。类目调整后重新提审，再申请接口。

## 4. 辅助图片要求（决定成败）

提交 2–3 张截图，必须能证明"业务真实用到定位"：

| 截图 | 内容 | 证明什么 |
| --- | --- | --- |
| 图 1 | 「附近」栏目页：顶部**开启定位**引导卡 + 开启定位按钮 | 功能入口真实存在，定位是功能必需 |
| 图 2 | 点击后弹出的**系统定位授权弹窗** | 请求时机合法合规 |
| 图 3（最关键） | 授权后的**附近帖子列表，卡片带距离**（如"1.2km · 12:30"） | 定位数据真的被用于展示 |

**必须遵守：**

- 用**微信开发者工具或真机**截取真实运行页面，**不要用设计稿 / 原型图**（审核直接拒）。
- 每张图用**红框 / 箭头 + 文字标注**圈出"开启定位按钮""1.2km 距离"等关键元素，让审核员 3 秒看懂。
- 图 3 获取方法：开发者工具开启**定位模拟**（自带 IP 定位），附近页即可显示带距离的帖子，直接截图；无真实帖子可先用测试 / 种子帖。
- 申请原因与图片**一一对应**：原因写"展示 50km 内晒吃 + 距离"，图片就必须有"附近列表 + 距离"。

**2026-08-14 实际驳回记录**：驳回原因"提供的申请原因 / 辅助图片 / 网页 / 视频内容无法确认申请接口使用场景"——此类驳回 90% 因辅助图片不合格（非真实截图 / 无定位用途 / 无标注），按上表补齐后重新提交。

## 5. 重新提交时的核对清单

- [ ] 服务类目已添加/调整为开放类目（餐饮服务-点餐平台）
- [ ] `app.json` 已声明 `permission.scope.userLocation`（项目已声明 ✓）
- [ ] 申请接口**只勾 `wx.getLocation`**，不勾持续定位
- [ ] 申请原因用第 2 节模板，落足业务闭环
- [ ] 辅助图片能对上申请原因（附近页 + 距离展示）
- [ ] 代码里已实现"用户拒绝 → 引导开启定位"（不强制授权，审核也更友好）
